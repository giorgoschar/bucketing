# Phase B Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** a month review on the 1st and a live statement for every past month.

**Spec:** `docs/superpowers/specs/2026-10-10-phase-b-review-statements-design.md`. It is binding and holds the contracts (§3), the copy (§4) and the required tests (§6). Where this plan and the spec differ, the spec wins; say so in your report.

**Architecture:** two parallel streams cut from `p10/phase-b`:

| Stream | Branch | Worktree | Postgres DB |
|---|---|---|---|
| **S** (server) | `p10/phase-b-s` | `~/expenses-p10-s` | `t_phaseb` |
| **W** (web) | `p10/phase-b-w` | `~/expenses-p10-w` | none |

Stream W hand-types the three response shapes from spec §3 in `web/src/features/insights/statements/types.ts`. Integration merges S then W, runs `npm run gen:api`, and replaces the hand-typed shapes with aliases of the generated ones.

## Global Constraints

- **Migration:** exactly one, `d6e7f8a9b0c1`, revising `c5d6e7f8a9b0`. If that id is already taken, pick another, keep one head, and report it.
- **Reuse, do not re-derive:** every statement number comes from the service that already produces it for its own screen (`in_out` / `monthly_in_out`, the planning entries, the `budget_rows` spending rule, `bill_change.assess`, `wallet_summaries`, `categories_vs_usual`). Where a service only works for "today", give it a month or date argument with the current behaviour as the default; do not copy its logic.
- **API compatibility:** existing JSON keys and types are unchanged; only additions.
- **Privacy:** no stash amount in any Phase B response.
- **Phone:** every desktop CSS rule sits inside `@media (min-width: 1024px)`.
- **Tests:** do not modify or weaken existing test cases. If a change makes an old assertion wrong by design, stop and report it.
- **Copy:** verbatim from the spec.
- **Layout:** no horizontal page scroll at 390×844 or 1440×900; 44 px targets on the phone; `.ui-num` in running text wraps.
- **Bundle:** the main chunk stays under the 340 kB guard; new screens are lazy and precached.
- **Commits:** one per task, by explicit path. No pushing and no subagents.

## Review Focus

1. **A month with no data at all,** between two months with data: the statement opens with zeros and the quiet empty lines, and the list shows it.
2. **The turn of the year:** on 3 January the review is for December of the year before, with 3 days left.
3. **An entry edited after the review:** the statement shows the new numbers and still says "Reviewed on …".
4. **Two members pressing Done at the same moment:** one row, no error for either.
5. **A household whose first data is this month:** no review, an empty list, no Home row, no notification.

Each has a test in the task that owns the code (S2, S2, W2, S3, S3 and W3).
