# Plan › Cash Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** add Plan › Cash to the React PWA: the stash, monthly wallets, movements, a Take / Put back / Still have sheet, a stash recount, "Log it", and a Home attention row. The server gets a `stash_count` kind, `GET /cash/wallets` and typed cash responses.

**Architecture:**
- Two parallel streams in separate worktrees:
  - **B**, the server, on branch `p4/cash-b`.
  - **W**, the web, on branch `p4/cash-w`. W codes against the API contract in spec §3, using hand-written types in `web/src/features/plan/cash/types.ts`.
- An integration step merges B, then W, onto `p4/cash`. It re-runs `npm run gen:api` and switches `types.ts` to aliases of the generated schema types.

**Tech Stack:**
- Server: FastAPI, SQLAlchemy and Pydantic v2. pytest, with SQLite locally and Postgres (`t_cash`) for the cash tests.
- Web: React 19, TanStack Query 5 via `useCachedQuery`, `useOnlineAction` (`web/src/data/onlineAction.ts`), Vitest and Testing Library.

**Spec:** `docs/superpowers/specs/2026-10-08-cash-design.md`. It is binding. Section numbers below (§) refer to it.

## Global Constraints

- **No database migration.** The alembic head stays `d0e1f2a3b4c5`.
- Keep the JSON shape of the existing `/api/v1/cash/movements` and `/summary` responses exactly. The composer's `useStash` reads `.stash`.
- Cash writes in the web app are online-only, through `useOnlineAction`, the same way the Settings hooks use it (`features/settings/profileHooks.ts`). They never go through the offline queue.
- Keys in `data/keys.ts` are additive only. Never rename an existing key.
- Do not modify or weaken existing test cases. Adding new ones is fine.
- Copy text is taken verbatim from the spec, with euro amounts formatted by the existing `Money`/format helpers.
- At 390×844 there is no horizontal overflow. Any `.ui-num` inside running text must be able to wrap.
- Commit by explicit path, push nothing and spawn no subagents.

## Review Focus

1. A recount followed by a backdated take, then deleting the recount. The balance must equal the count minus the later take, and the delete rule must apply (spec §3.1).
2. A member taking from another member's stash must never see that member's balance or recount rows, in either direction.
3. "Log it" must create no second take. `took_cash` must be false in the POST body.
4. Offline: cached data renders, every write is disabled, and there is no spinner loop when nothing was ever cached.
5. Still have with amount 0 must be accepted and saved, not rejected as empty.
