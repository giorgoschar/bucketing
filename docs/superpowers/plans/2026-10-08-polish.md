## Contracts (the server produces them, the web streams consume them)

### C1 `GET /api/v1/transactions/totals`
- Takes the same query params as `GET /transactions` (the `FeedQuery` filters).
- Returns `{count: int, out: Money, in: Money}` over **all** matches. Money is serialised the way `TransactionOut.amount` is.
- Totals are in household currency, using the same converted amount the Insights totals use.
- Soft-deleted rows are excluded.
- The query is a single aggregate, never a loop over rows.

### C2 `PATCH /api/v1/stock/{id}`
- **Already accepts:** `min_quantity` and `track_price`.
- **Now also accepts:**
  - `name` (1–200 characters, trimmed)
  - `brand`
  - `unit`
  - `unit_quantity` (> 0 or null)
  - `barcode` (`clean_barcode`)
- **Errors:**
  - a barcode already used by another active product in the household returns 409, with `detail` "Another product already has this barcode";
  - an empty name returns 422.
- **Returns:** the list item.

### C3 `POST /api/v1/stock/{id}/prices`
- Records the price you paid.
- **Body:** `{price: number > 0, retailer: string, date?: YYYY-MM-DD (default today, not in the future)}`.
  - `retailer` is a known chain code from `retailer_label`'s map, or `"other"`.
- **Stored as:** a `PriceSnapshot` with `source='manual'` (new column, see M1), upserted per product, retailer and day.
- **Returns:** the detail (`GET /stock/{id}` shape).
- Manual snapshots feed `cheapest`, `prices_today`, `history` and advice exactly as PosoKanei snapshots do.
- **`GET /stock/retailers`** returns `[{code, name}]` for the picker.

### C4 Untick by item
- `DELETE /api/v1/stock/shopping/ticks?stock_item_id=…` removes **the** active tick for that item, whoever created it, and returns 204.
- It is idempotent: when there is no active tick it also returns 204.
- The existing `DELETE /ticks/{id}` is unchanged.

### C5 Cash idempotency
- `POST /api/v1/cash/movements` accepts an optional `client_id` (uuid4).
  - The same id from the same household within 24 h returns the original movement, with 201 and nothing new created.
  - For a take-and-log, that also means no second expense.
- The row is locked the way the stock adjust replay is locked: the actor's stash rows, via a per-user advisory or row lock.
- Two simultaneous recounts are serialised.

### C6 Wallet terms
- The `/cash/wallets` member `wallet` gains `logged_cross_month: Money` and `over_logged: Money`. These are the two terms the card leaves out today, according to the Cash final review m2.
- Read `app/services/cash.py` `_breakdown` and name them exactly as the formula uses them. If the formula needs different names, record a ruling in the report and use those names.
- The card shows these terms whenever they are non-zero, so that the shown sum always equals `not_yet_logged`.
- The viewer's own `taken` is floored at 0, as it already is for others.

### M1 Migration `f2a3b4c5d6e7`
- Index on `shopping_lines.stock_item_id`.
- `cash_movements.client_id`: String(36), nullable, with a non-unique index on `(household_id, client_id)`.
- `price_snapshots.source`: String(16), nullable, server default `'posokanei'`.
- Add the migration to `tests/test_migrations.py` and `tests/test_planning_upgrade.py`, with additional cases only.
