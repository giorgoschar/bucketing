# Phase A Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** a desktop layout (sidebar, Activity table with a detail pane, Add side panel), a history for each recurring item with optional usage, and an upgraded bill-change alert.

**Spec:** `docs/superpowers/specs/2026-10-09-phase-a-desktop-bills-design.md`. It is binding and holds the contracts (§3), the copy and the required tests (§7). Read the sections your tasks name before you start. Where this plan and the spec differ, the spec wins; say so in your report.

**Architecture:** three parallel streams cut from `p8/phase-a`:

| Stream | Branch | Worktree | Postgres DB |
|---|---|---|---|
| **S** (server) | `p8/phase-a-s` | `~/expenses-p8-s` | `t_phasea` |
| **D** (web: desktop shell, Activity table, Add panel) | `p8/phase-a-d` | `~/expenses-p8-d` | none |
| **H** (web: usage, Bills list, history, Home row, desktop Insights) | `p8/phase-a-h` | `~/expenses-p8-h` | none |

The web streams hand-type the new API types from spec §3 in one file each (`web/src/features/insights/bills/types.ts` for H, none needed for D beyond the `sort` string). Integration merges S, then D, then H, runs `npm run gen:api`, and replaces the hand-typed types with aliases of the generated ones.

**Already on the base branch:** `web/src/ui/useIsDesktop.ts` (`useIsDesktop()`, `DESKTOP_QUERY`). Both web streams import it. Neither edits it. Its test file shows how to stub `matchMedia` in a test.

## Global Constraints

- **Migration:** exactly one, `a3b4c5d6e7f8`, revising `f2a3b4c5d6e7`. Additive, with a working downgrade. No enum changes.
- **API compatibility:** existing JSON keys and types are unchanged; only additions. Pin a shape with a snapshot test before you touch its route.
- **Phone unchanged:** every desktop CSS rule sits inside `@media (min-width: 1024px)`. No existing rule is edited to make room for desktop, except lifting a `max-width` inside that media query. `matchMedia` is absent in the test environment, so every existing test runs as the phone.
- **Tests:** do not modify or weaken existing test cases. Adding cases is fine. If a change makes an old assertion wrong by design, stop and report it.
- **Copy:** verbatim from the spec.
- **Layout:** no horizontal page scroll at 390×844 or 1440×900; targets ≥ 44 px on the phone; `.ui-num` in running text must wrap; text contrast ≥ 4.5:1; a visible focus ring on every desktop control.
- **Bundle:** the main chunk stays under the 340 kB guard in `check-sw.mjs`. New screens are lazy (`web/src/screens/lazy`).
- **Money and usage:** `Decimal` on the server, JSON numbers on the wire.
- **Commits:** one per task, by explicit path. No pushing and no subagents.

## Review Focus

1. **A seasonal bill.** Electricity at €84 in January after €40 in October, with €80 last January, must not alert. The same bill with no entry last January compares with the last 3.
2. **Usage of 0, or usage on one side only.** No division by zero, no reason, and the amount comparison still works.
3. **Resizing across 1024 px with the Add panel or the detail pane open.** Nothing typed is lost and the URL still means the same thing on the other side.
4. **A reload with `?add=1` or `?edit=<id>` in the URL,** on desktop and on the phone. The phone must land on a working screen, not a blank one.
5. **An amount sort across pages.** Rows with equal amounts must not repeat or go missing between pages.

Each of these has a test in the task that owns the code (S2, S2, D3, D3, S4).
